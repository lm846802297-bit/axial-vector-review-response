# Repository instructions — axial-vector referee-response project

Before doing **any task** in this repository, read:

1. [审稿回复信与论文修改清单写作规范](审稿意见-gpt/写作规范/审稿回复写作原则.md)
2. [论文正文待同步修改清单（2026-11-03）](审稿意见-gpt/当前执行/论文修改与一致性核查/2026-11-03/论文正文待同步修改清单_2026-11-03.md) whenever the task touches the referee response, manuscript consistency, or planned manuscript edits.

For every task that writes, edits, reviews, audits, or evaluates the referee-response letter:

- Keep the referee-facing response letter strictly separate from internal manuscript-change tracking.
- The response letter is written only for the PRD referee. It must directly answer each point and retain the necessary derivations, equations, benchmarks, quantitative comparisons, citations, and scientific scope qualifications.
- Do not put internal task status, version mismatches, pending manuscript edits, branch/PR/CI information, or workflow notes in the referee-facing letter.
- Never claim a manuscript edit has been completed unless the actual manuscript source has been changed and checked. If an edit is pending, record it only in the internal checklist; do not report the internal state to the referee.
- Do not mistake a necessary scientific limitation for an internal progress report. State genuine model and experimental applicability limits accurately (for example, the PMNS block structure, the spin-one assumptions behind a search interpretation, or the conditional Higgs-portal benchmark).
- Preserve complete scientific reasoning. Remove only repetition, redundant parameter definitions, unrelated background, and disclaimers that add no argument.
- Check consistency across related Major and Minor points so they use the same assumptions, conventions, and scope.

The detailed and authoritative rules are in the linked writing-standard document. If older chats, drafts, or historical files conflict with it, follow the writing standard and the author's latest explicit instruction. Do not modify the paper source when the task is limited to the referee response or its internal checklist.
