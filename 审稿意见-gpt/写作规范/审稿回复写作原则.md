## 1. 两类文件的职责必须严格分开

### A. 审稿回复信：只面向审稿人

审稿回复信必须是一份正式、完整、可直接提交给 PRD 审稿人的文件。它的任务是正面回答审稿人提出的问题，并用论文的模型构造、理论推导、数值结果和实验文献支撑回答。

回复信应当：

1. **逐点回答审稿意见。** 保留审稿人的原始问题或关键引文；对不同子问题分别作答，不用笼统段落替代具体回应。
2. **先给出物理回答，再展开论证。** 开头直接说明模型给出什么结构、论文得到什么结果、该结果如何回答审稿人的疑问。
3. **保留完整且必要的科学论证。** 对关键结论给出推导过程、关键公式、规范荷或参数关系、数值 benchmark、与实验数据的定量比较及相关文献。
4. **明确结果的物理适用条件。** 说明所采用的模型、参数基准、近似、质量/能量区间和实验解释条件。必要的科学限定是论证的一部分，不是需要隐藏的“缺点”。
5. **准确描述论文实际做出的工作。** 只有在对应正文修改确实已经完成并核验后，才可以写 “we have revised/added/removed/shortened the manuscript”。如果正文修改尚未落实，不得虚构已修改；可以直接陈述已经成立的模型结构、推导和物理结果，而不汇报内部编辑进度。
6. **以发表判断所需的充分性为尺度。** 论证要完整、证据充分、边界清楚，但不把回复信写成整篇论文的重复抄写，也不扩展成无关的全面研究综述。

回复信不得包含：

- 内部任务、待办清单、修改计划、负责人、分支、PR、commit、CI 或版本管理信息；
- “论文与回复信版本不一致”“正文尚未同步”“尚未完成某项编辑”等内部状态汇报；
- 与当前审稿问题无关的未完成计算、未来研究清单或自我评价；
- 用将来时承诺代替对现有模型和结果的直接回答；
- 没有证据支持的“已完成”“已排除”“全参数空间允许”等结论。

**重要区别：不汇报内部进度，不等于隐瞒科学限制。** 回复信可以、也必须陈述真正影响物理结论的模型适用范围和实验适用性；但不向审稿人汇报团队内部如何安排、何时完成或在哪个文件中记录这些事情。

## 2. 科学论证：应该保留什么

以下内容只要对回答审稿意见有实质作用，就应当保留，不能为了追求短篇幅而删掉：

- 关键推导步骤、规范荷分析、质量矩阵结构和对称性论证；
- 决定结论的公式、定义、近似条件和参数关系；
- 已经获得且与问题直接相关的数值计算和 benchmark；
- 与实验数据、实验灵敏度或已发表限制的定量比较；
- 对每一个独立子问题的明确回答；
- 必要的模型适用范围、有效理论边界和实验解释条件；
- 对容易混淆的物理量、参数或不同实验过程的区分。

例如：

- 可以明确说明最小模型的 PMNS 结构不能满足观测到的电子味混合；这是物理结论，不是内部进度汇报。
- 可以区分 Belle II 的矢量媒介子与已发表的 spin-0 标量分析，并说明其标量耦合基准和分支比是否适用于径向标量 (s)；这是实验适用性判断。
- 可以说明 Higgs portal 是规范允许的，negligible-mixing 仅是特定 matching benchmark，并明确近简并区不适用小混合近似；这是必要的模型条件。
- 可以说明某个超新星标记代表 free-streaming threshold，而不是完整的 SN exclusion；这是对实验/天体物理结果含义的准确限定。

## 2.1 模型适用范围与跨问题一致性（强制）

本项目统一遵守 [DEC-15：统一模型适用范围与审稿一致性原则](../项目规范/研究决策与不可回退事项.md)。

1. **原论文模型是默认基准。** 除非作者明确批准修改论文模型，所有非中微子审稿问题均以原论文 \(S+\mathrm{VLL}\) 单 VEV UV 模型的场内容、规范荷、拉格朗日量和参数关系为依据。
2. **中微子问题独立处理。** Major Point 3 和 Major Point 4.1 可以讨论专门的中微子机制；不得将这类机制扩展到 Major 1、2、4.2、4.3、4.4 或其他非中微子问题。
3. **不同模型的公式不得混用。** 不得把扩展模型的质量关系、VEV、混合角、质量本征态、衰变宽度、产生率或实验限制直接用于原论文模型。跨模型复用前，必须从目标模型重新推导或完成明确 matching，并核对归一化、近似条件和适用过程。
4. **回复内容不等于论文内容。** 回复信中讨论一种可能的扩展，不代表原论文已经加入该扩展，也不代表原论文其他现象学结果已在扩展模型中重新验证。
5. **每个问题都要标明模型边界。** 逐点核对模型身份、场内容、理论输入、参数关系、近似条件、适用范围和证据来源；相关 Major/Minor 必须保持内部一致。

**核心目标：** 本轮任务是回应审稿人对原论文的质疑，而不是借审稿过程把原论文逐步扩展成另一个 UV 模型。

### 2.2 论证充分性原则：从结论陈述到可复核的物理论证（强制）

**核心规则：审稿回复不仅要“提到”审稿人提出的问题，还必须给出足以让审稿人理解、检查并判断结论的论证。** 主题覆盖不等于回答充分；仅有结论句、孤立公式或没有来源的数值，均不能自动视为完成了该问题的回应。

对每个实质性审稿问题，必须根据问题性质建立相应的论证链条：

1. **直接回答与物理原因。** 先明确回答审稿人究竟问了什么，再解释结论由何种物理机制、对称性、相互作用或运动学条件产生。不能只给“是/否”“允许/不允许”“次要/不相关”等结论而不解释原因。
2. **公式来源与推导联系。** 不能只罗列公式。应说明公式来自哪一项拉格朗日量、规范荷、质量矩阵、有效算符、运动方程、振幅定义或已引用文献；给出足以看清关键逻辑的推导步骤，并说明采用了哪些近似。无需重复整篇论文的推导，但不能省略决定结论的逻辑环节。
3. **数值、benchmark 与物理意义。** 不能只报告一个数值。应明确输入参数、benchmark 选择、归一化约定、动量/质量点、近似条件及数值代表什么；说明该数值如何回答审稿人的疑问，以及它能支持和不能支持哪些结论。无法从计算、原始数据或可靠来源复核的数值，不得作为已验证结果写入回复信。
4. **实验适用性与模型映射。** 不能只说某项实验限制“不适用”“较弱”或“可以忽略”。应解释实验实际探测的产生机制、耦合结构、自旋、衰变道、分支比、寿命、接受度或统计定义中哪些条件与本文模型相同、哪些不同；说明能否直接使用、需要何种匹配/重铸，以及当前比较的适用范围。若没有完成相应重铸，必须相应收窄主张，不得把质量覆盖写成模型排除。
5. **多子问题逐项作答。** 审稿意见包含多个独立疑问时，必须逐一回应。可以用一个连贯段落组织，但每个子问题都应有可识别的答案和证据；不能用一句总体结论替代多个不同的物理或实验回答。

**适用方式：** 上述五项是论证检查维度，不是要求每一条回复机械地堆入五组公式或固定篇幅。简单的术语澄清可以简短；涉及模型机制、定量结论或实验限制的问题，则必须提供与其复杂度相称的推导和证据。判断标准是论证是否闭合、可复核，而不是段落长度。

**与 §3.1 的关系：** §3.1 判断已有内容是否具有独立论证功能、因而不能被误删；本节判断当前回复是否已经提供了足够的物理原因、公式来源、定量证据和适用条件。前者防止删掉必要内容，后者防止只留下结论而缺少支撑。两者共同要求论证完整性优先于篇幅。

## 3. 文字层面：可以精简什么

在不损失论证链条的前提下，可以精简：

- 同一个物理结论在相邻段落中的重复陈述；
- 已经定义过的参数、符号和 benchmark 的重复解释；
- 与审稿人当前问题无关的背景介绍；
- 不提供新证据、不增加推理步骤的免责声明；
- 多次重复“本文范围有限”“未来还可以研究”等泛化句子。

精简的判断标准不是字数，而是该句是否提供新的物理信息、证据、推理或必要限定。**不能为了让回复信更短而删去关键公式、定量结果或子问题的独立回答。**

### 3.1 论证功能优先原则：不得把表面重复当作删除依据（强制）

**核心规则：不要为了文字简洁而删除具有独立论证功能的内容。** 判断能否合并，必须先判断两段文字承担的物理和论证功能是否相同；主题相同、术语相同或都包含“限制性措辞”，并不意味着它们可以互相替代。

修改前，应识别相关内容分别承担的功能。至少区分：

- 对审稿人问题的直接回答；
- 物理定义、模型假设和参数约定；
- 推导步骤、闭式解析表达式和公式之间的逻辑联系；
- UV 理论、EFT 算符及 UV--EFT matching；
- benchmark、数值结果、误差和实验定量比较；
- 独立交叉验证及其实际验证对象；
- 近似条件、质量/能量范围和适用域；
- 不同图、不同计算子集、不同过程各自的适用范围；
- 尚未包含的图、反项、soft/counterterm 扇区及其他必要限制。

**以下内容即使相邻出现或措辞相似，也不能仅凭“重复”而合并：**

1. 不同圈图或不同拓扑子集各自的适用范围；
2. UV hard 部分与 EFT soft 部分各自的定义、保留项和遗漏项；
3. 数值交叉验证“验证了什么”与“没有验证什么”；
4. 一个近似在某个 benchmark 上成立、但不能推广到其他质量区间的条件；
5. 对完整物理极点、完整 UV--EFT 匹配或完整实验排除尚未闭合的独立说明。

Major Point 1.3 是具体范例：scalar-bubble 子集不是完整两圈 UV--EFT matched self-energy；bubble-plus-contact soft 子集不是全部同阶 EFT soft insertions/counterterms；费米子 hard 子计算的数值一致性也不意味着剩余 soft/counterterm sectors 已闭合。这三种说明涉及不同的对象和验证层次，必须分别保留。相同原则适用于其他 Major/Minor Points，不限于 Major Point 1.3。

**允许合并的必要条件：**

1. 逐句确认被合并内容表达的是同一个物理命题、同一组适用条件和同一种证据功能；
2. 合并后仍保留完整公式、推理、数值、benchmark、引用和必要限定；
3. 合并不会使读者误以为某个子集等同于完整计算，或把局部验证误解为整体验证；
4. 在修改记录中说明原内容在哪里、合并后由哪一句或哪一段完整承接。

如果只是重复介绍已定义的符号或同一推导步骤，可以使用交叉引用；但交叉引用不能代替本段独有的结果、验证证据或适用范围。

**删除与作者确认：**

- 删除或实质性压缩闭式公式、推导步骤、UV--EFT matching、benchmark、数值结果、验证精度、近似条件、实验比较或计算限制，均属于科学内容变更，不是普通文字润色。
- 任何此类变更必须在 PR 中列出原内容、删除/合并理由、替代位置及对论证链条的影响；不得藏在大段重写或格式调整中。
- 若删除会移除一项独立的物理结论、计算证据、验证边界或适用条件，必须先取得作者明确同意；未获同意时保留原文。
- 不能证明某内容确实冗余时，默认保留，而不是默认删除。

因此，文字精简的目标是消除真正重复的信息，而不是减少论证环节。**论证完整性优先于篇幅。**

## 4. 不要混淆科学限定与内部进度汇报

| 不合适的内部进度表达 | 正式回复应采用的论证方式 |
|---|---|
| “The revised manuscript will include ...” | 直接说明模型结构、理论结果或实际已经完成的修改 |
| “The manuscript has not yet been updated ...” | 不汇报内部编辑状态；如需说明正文改动，先完成并核验实际修改 |
| “We have not completed the collider recast ...” | 说明已发表实验结果的产生机制、假设、适用范围，以及哪些解释不能直接移植 |
| “This issue remains to be addressed ...” | 给出当前模型和本文研究范围内能够严格成立的结论 |
| “The current branch/PR contains ...” | 删除版本管理内容，不属于审稿人需要的信息 |

上表不是要求回避实质性问题。若某项未完成工作意味着现有证据不足以支持准备写入回复信的结论，应当降低或收窄该结论；不得把未计算的结果写成已验证。正确做法是调整科学主张，而不是把内部任务清单塞进回复信。

## 5. 语气和论证组织

每一条回复建议采用以下逻辑：

1. **直接回答审稿人的问题。** 用一至两句说明结论。
2. **给出模型或理论依据。** 写出必要的拉氏量、规范荷、矩阵、公式或推导。
3. **给出定量支撑。** 列出 benchmark、数值、参数范围和实验比较。
4. **解释物理意义。** 说明该结果如何解决审稿人的具体疑问。
5. **给出必要的适用范围。** 只保留会影响结论正确性的条件，不展开内部工作流程。

语气应正式、直接、准确、有把握。避免防御性长篇解释，也避免通过大量自我批评来显示谨慎。

以上五步不是机械扩写模板，而是组织完整论证的逻辑顺序。对简单问题，若某一步与问题无关，不必人为添加；对包含多个子问题的复杂意见，应分别完成对应论证，不能因为总体回复已经较长就默认每个子问题都已回答充分。

### 5.1 总体回复与具体子回复的层级结构（强制）

所有 Major Points 统一采用“简洁总述、充分子回复”的两层组织方式；该结构用于明确论证职责，不是机械限制篇幅。

1. **总体回复（Overall Reply）简洁。** 在审稿人该 Major Point 的总体意见之后，用一至数句直接回答核心疑问，概括主要结论、模型边界，并指出后续子回复分别处理哪些具体问题。总体回复不重复完整推导、长公式链、benchmark 表格或已经在子回复中给出的实验比较。
2. **具体子回复（Point-by-point Replies）充分。** 每个独立子问题应在对应位置给出与其复杂度相称的物理原因、公式来源和必要推导、benchmark 输入、定量结果、实验映射及适用条件。不得以总体回复已经概括结论为由，省略子问题本身所需的证据。
3. **按审稿人的问题结构组织。** 审稿人已经编号的子问题沿用其编号；没有独立编号、但包含不同物理疑问时，可以使用简短的主题小标题组织，不得人为制造新的审稿人编号。
4. **跨子问题避免重复，但不牺牲可读性。** 若完整推导已经在同一 Major Point 的另一子回复中给出，后续子回复可以交叉引用；但仍须直接回答当前问题，重申决定结论的物理条件，并保留理解该回答所必需的关键关系式。不能仅写“见上文”而不说明当前问题的答案。
5. **结构调整不得改变证据归属。** 公式、数值、benchmark、文献依据和适用范围可以移动到最直接回答相应问题的位置；移动后必须在内部记录中标明原位置、目标位置和论证功能。只有确认属于同一命题、同一适用条件且没有独立论证作用的重复总结，才可以合并。

因此，正式回复应让审稿人先迅速理解每个 Major Point 的总体结论，再在对应子回复中检查充分的物理论证。篇幅以论证闭合和可复核为准，而不是越短越好或越长越好。

## 6. 每次项目任务的强制工作流程

每次在本仓库开展回复信撰写、修改、审查或一致性验收时：

1. 先阅读仓库根目录 `AGENTS.md` 和本文件，不得跳过。
2. 读取当前 main 上的正式回复信文件，确认最新提交；不要从聊天记录或旧分支直接续写。
3. 对照 [论文正文待同步修改清单](../当前执行/论文修改与一致性核查/2026-11-03/论文正文待同步修改清单_2026-11-03.md)，明确哪些内容属于内部正文同步事项。
4. 需要核对物理决策时，查阅对应会议记录、当前论文事实基线、模型推导和实际计算/文献证据；不能用历史工作稿覆盖当前决策。
   - **模型一致性前置检查：** 在推导或编辑前明确目标模型。原论文单 VEV 模型是所有非中微子问题的基准；只有 Major 3/4.1 可讨论专门中微子机制。不得把扩展模型公式、参数或实验限制未经重新推导直接移植到原模型。
5. 修改前建立受影响 Major/Minor Point 的内容基线，标出关键公式、推导、匹配关系、benchmark、数值验证、近似条件和各计算子集的适用范围。
6. 修改回复信时，只把审稿人需要看到的科学论证写入回复信；把正文同步任务、状态和前后对照写入内部清单。
7. 对每项修改标注类型：新增、物理纠错、表述澄清、真正重复内容合并、删除或替换。不能将科学内容删除伪装成一般文字润色。
8. 修改后逐项对照修改前后的内容基线，检查每条审稿意见是否得到独立回答，相关 Major/Minor 之间是否使用相同的模型假设、参数约定和适用范围；并按 §2.2 对每个实质性问题进行论证充分性检查，不能把“已覆盖该主题”直接判定为“已充分回答”。
9. 单独检查所有删除、合并和大幅改写：列出原内容、论证功能、处理理由、替代位置及对论证完整性的影响。没有独立论证功能的纯重复可以合并；有独立功能的内容必须保留，除非作者明确批准删除。
10. 在 PR 描述中必须引用本规范的具体条款（至少引用 §3.1、§6 和 §7），并附“论证完整性核查”摘要，说明保留项、增补/纠错项、删除/合并项（没有也须明确写“无”）和实际执行的验证。
11. PR 审查者必须检查实际 diff，而不能只依据 PR 描述中的自我声明；核对删除清单是否覆盖所有实质性删除，并检查被合并内容是否确实具有相同论证功能。审查者还必须在正式 review record 中引用本规范 §3.1、§6 和 §7，明确记录论证完整性核查结论及未解决项。
12. 在报告工作结果时，分别说明回复信文件和内部清单的变化；不得将内部清单状态写进审稿人可见文件。

### 6.1 回复信相关 PR 的强制核查模板

每个修改正式回复信或其直接论证记录的 PR，必须在 PR 描述中加入以下项目并链接本文件；PR 审查者还必须在正式 review record 中引用本文件 §3.1、§6 和 §7，确认是否满足这些要求：

- **规范依据：** [审稿回复写作原则](本文件)，列明实际采用的条款编号（至少 §3.1、§6、§7）。
- **影响范围：** 修改了哪些 Major/Minor Point，以及对应的源文件和段落。
- **模型边界：** 明确使用原论文模型还是独立扩展模型；列出场内容、拉格朗日量/规范荷、参数关系和适用点。若讨论中微子扩展，说明其仅限 Major 3/4.1，且不代表论文已加入该机制。
- **论证充分性（依据 §2.2）：** 对每个受影响的 Major/Minor Point，列出审稿人的核心疑问、物理原因、公式/推导来源、数值 benchmark 及其意义、近似和适用范围；多子问题逐项核对。明确哪些内容已充分、哪些仍缺少证据；不能用“已涉及该主题”代替充分性判断。
- **内容保留：** 关键公式、闭式表达式、推导、UV--EFT matching、benchmark、数值结果、交叉验证、近似条件和适用范围是否保留。
- **新增/纠错：** 新增了什么物理依据，纠正了什么错误；区分物理修正与文字润色。
- **删除/合并台账：** 明确写“无”，或逐项列出原文/位置、论证功能、处理理由、替代位置及影响。任何独立论证功能的删除须有作者明确批准。
- **验证边界：** 逐项区分已执行的 TeX 静态检查、完整编译、PDF 视觉检查、数值复算、脚本测试和 CI；未执行的项目明确标为未执行，不得推断通过。

若 PR 仅修改内部文档而未修改回复信正文，也应说明这一点；若 PR 涉及多个 Major/Minor Point，应按点分别核查，不能用一条笼统的“未丢失内容”代替。

如果本规范与旧聊天记录、历史工作稿或旧版本中的写作要求冲突，以本文件和作者最新明确指示为准；涉及物理事实时，仍必须以原始论文、模型定义、可靠文献和可复核计算为依据。

## 7. 正式提交前自检

### 论证完整性与修改 Diff

- [ ] 修改前是否读取当前 main 的权威回复信，并建立受影响 Major/Minor Point 的内容基线？
- [ ] 是否逐项核对公式、闭式表达式、推导、UV--EFT matching、benchmark 和数值结果？
- [ ] 是否明确区分原论文单 VEV 模型与 Major 3/4.1 的专门中微子讨论？
- [ ] 是否错误移植了扩展模型的质量关系、混合角、衰变宽度、产生率或实验限制？
- [ ] 回复信中讨论的候选机制是否被误写成原论文已经采用的场内容？
- [ ] 每个推导/PR 是否说明模型、场内容、理论输入、参数关系、近似和适用范围？
- [ ] 是否保留每项独立数值验证及其实际验证对象、精度和未覆盖部分？
- [ ] 是否分别保留不同图、不同计算子集和不同 EFT 扇区的适用范围？
- [ ] 是否保留近似条件、质量/能量范围、近简并区限制及尚未闭合的 soft/counterterm 说明？
- [ ] 所有删除、合并和大幅改写是否有单独台账，列出原文、论证功能、理由和替代位置？
- [ ] 被合并的内容是否确实具有相同的物理命题、适用条件和证据功能，而不是仅仅措辞相似？
- [ ] 是否避免把局部子计算或局部数值验证表述成完整模型计算或完整物理预测？
- [ ] 是否已在 PR 描述中引用本规范 §3.1、§6 和 §7，并填写强制核查模板？
- [ ] 若删除独立物理结论、证据或适用范围，是否取得作者明确同意？

### PR 审查者结论

- [ ] 已检查实际 diff，而非仅阅读 PR 摘要。
- [ ] 已核对删除/合并台账与实际 diff 一致。
- [ ] 已确认没有未登记的实质性内容删除。
- [ ] 已确认科学验证声明与实际执行证据一致。
- [ ] 对未通过或未完成的项目，已明确标注阻塞项；不得以文档格式检查代替物理验证。

### 审稿人视角

- [ ] 每条 Major/Minor 是否都直接回答了审稿人的实际问题？
- [ ] 每个独立子问题是否都有独立、明确的回应？
- [ ] 是否解释了关键结论的物理原因，而不只是陈述结论？
- [ ] 关键公式是否说明了来源（拉格朗日量、规范荷、质量矩阵、有效算符、振幅定义或文献）及必要推导步骤？
- [ ] 每个重要数值是否给出 benchmark 输入、归一化、近似条件和物理意义，并可由计算或可靠来源复核？
- [ ] 对实验限制的适用性判断是否解释了产生机制、耦合/自旋/衰变/接受度假设与本文模型的异同？
- [ ] 多子问题是否逐项回答，而不是仅以总体结论代替？
- [ ] 关键公式、推导、benchmark 和实验比较是否充分？
- [ ] 科学限定是否具体、准确且与模型假设一致？
- [ ] 是否把“未被某项约束排除”误写成“已经证明允许”？
- [ ] 是否把其他自旋或其他模型的实验解释错误移植到本模型？
- [ ] 是否存在重复文字、无关背景或没有论证价值的免责声明？

### 文件职责视角

- [ ] 是否误把内部任务、版本、PR、CI 或正文同步状态写进回复信？
- [ ] 是否声称完成了实际尚未落实的正文修改？
- [ ] 所有正文待同步内容是否都进入指定的内部论文修改清单？
- [ ] 回复信与内部清单是否保持分离，且各自用途明确？
