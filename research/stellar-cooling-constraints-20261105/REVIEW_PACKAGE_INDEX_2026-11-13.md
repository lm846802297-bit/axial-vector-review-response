# Axial stellar-cooling collaborator archive index

## Canonical source layout

The collaborator package is built from the canonical research files; it does not keep a second extracted copy of the same files.

- research/stellar-cooling-constraints-20261105/: axial EFT calculation, reconstructed profiles, scan outputs, plotting, tests, and the independent Blinov B.13/B.16 research programme.
- research/stellar-cooling-original-uv-model-20261105/: original single-VEV model mapping and validation.
- research/stellar-cooling-two-vev-20261105/: two-VEV model mapping and validation.
- research/stellar-cooling-eft-literature-20261105/: independent literature-kernel implementation and checks.
- research/stellar-cooling-collaborator-archive-20261113/: collaborator guide, status matrix, figure audit, reviewer checklist, package builder, and dependency list.

The historical directory review_package_extracted/ is retired and removed from the current branch. Its duplicated source copies are not used as canonical inputs. The 12 unique metadata records for the original 12-part/75-member extraction are preserved under research/stellar-cooling-collaborator-archive-20261113/provenance/original-review-package/; this directory contains provenance only, not another copy of the source payload.

## Optional local ZIP handoff — not stored on GitHub

No generated collaborator ZIP is committed or published as a GitHub Release asset, and the current workflow no longer uploads one. The 13 ZIP artifacts uploaded by earlier runs were deleted and verified absent on 2026-11-13 in cleanup run #43358373940. Their IDs and original expiry times remain in research/BRANCH_INTEGRATION_AUDIT_2026-11-13.md as a historical deletion record. GitHub stores the canonical extracted/native source, data, reports, tests, figures, provenance, and checksum records.

When a collaborator specifically requests a single-file handoff, create it locally from a clean, pinned repository checkout and give the ZIP directly to that collaborator. Run from the repository root:

```bash
python -m pip install -r research/stellar-cooling-collaborator-archive-20261113/requirements-review.txt
python research/stellar-cooling-constraints-20261105/plot_constraints_loglog.py \
  --output-dir ../stellar-cooling-review-figures
python research/stellar-cooling-collaborator-archive-20261113/build_archive.py \
  --output ../Stellar_Cooling_Research_Archive_2026-11-13.zip \
  --generated-figures ../stellar-cooling-review-figures
```

The output path is outside the repository checkout, so the handoff ZIP is not accidentally committed. The workflow .github/workflows/build-stellar-cooling-review-archive.yml is optional validation-only; it does not create or upload a ZIP.

The large official SFHo-FRDM EOS source archives remain separately documented as original scientific input payloads in the sfho-frdm-v1.03-data release. They are not generated handoff archives and are not copied into the collaborator ZIP.

## Package contents and de-duplication

The package builder includes all tracked files from the four canonical research roots above, plus relevant stellar-cooling GitHub Actions workflows. It preserves each source subdirectory and records every file in SOURCE_FILE_CATALOG.csv with:

- original repository path;
- packaged path;
- inclusion / alias / external-release status;
- byte count;
- SHA-256;
- Git blob SHA when available;
- a short file description.

**Catalog generation:** SOURCE_FILE_CATALOG.csv is generated by build_archive.py inside the ZIP at 00_START_HERE/SOURCE_FILE_CATALOG.csv. It is intentionally not a separately tracked repository file; the builder and validation workflow are the source for reproducing it.

Byte-identical files are stored once and all aliases point to the canonical packaged copy. The historical review_package_extracted/ directory is excluded. The five large SFHo-FRDM ZIP payloads are not copied into the collaborator ZIP; they remain in the sfho-frdm-v1.03-data GitHub Release and are listed in the catalog with their manifest checksums. No private Garching raw simulation profile is included.

## Scientific status

This is a reproducible fixed-profile axial-EFT ballistic-cooling benchmark, not a final SN1987A exclusion. The pure-vector Blinov Fig. 7 end-to-end gate remains not passed at the 10 MeV strong-absorption tail. The axial production scan still uses an initial-muon-rest semi-Compton approximation rather than the full moving-muon B.13 thermal kernel. The mode-resolved versus scalar opacity prescription and background / energy-frame assumptions remain open physical gates.
